# Novel2Script 完整产品计划

## 产品定位

Novel2Script 是一款面向小说作者、编剧和改编策划者的 AI 辅助剧本改编工具。它的核心价值不是替代作者，而是把小说文本转换为可审校、可追溯、可继续修改的剧本结构初稿。

## 用户与场景

- 小说作者：希望快速评估作品是否适合影视化或短剧化。
- 编剧：希望从长文本中获得结构化场景、人物动作和冲突线索。
- 改编策划：希望用统一格式比较不同作品的改编潜力。
- 工作室团队：希望保留原文溯源，降低多人协作中的误读风险。

## 核心问题

小说改编不是简单摘要。系统需要把内心描写、叙述性信息和事件因果转换成可拍摄的场景、行动、对白和节奏，同时保留哪些内容来自原文、哪些内容是 AI 推断。

## 长期产品能力

1. 输入三章以上小说文本。
2. 解析章节、段落、人物、事件、关系和世界观线索。
3. 生成 Scene + Beat + Element 结构化 YAML 剧本初稿。
4. 使用 YAML Schema 做基础格式校验。
5. 使用确定性校验器检查缺字段、溯源覆盖率和结构一致性。
6. 使用多 Agent 审校角色给出 patch 建议。
7. 导出 Fountain，供编剧工具继续处理。
8. 在可视化工作台中展示原文、剧本、审校意见和变更记录。

## 第一阶段边界

当前阶段只建立项目骨架、文档体系、Schema 骨架、Prompt 模板和样例文件，不实现真实 AI 生成能力。

本阶段完成后，开发者应该能清楚知道：

- 主数据格式是什么。
- 文件应该放在哪里。
- 哪些模块未来负责 Schema、校验、导出和 Agent。
- 为什么审校 Agent 不能直接覆盖用户稿件。
- 如何准备 GitHub 分支、commit、issue 和 PR。

## 数据原则

- YAML 是主数据源，Fountain 是导出目标。
- 每个关键剧本元素尽量保留 `source_trace`。
- AI 推断、低置信度内容和需要人工确认的部分必须标记在 `ai_tags` 中。
- 样例文本必须自造或确认可公开使用。
- 用户上传文本默认视为隐私内容，不进入公开仓库。

## 成功标准

- 项目结构清晰。
- 文档入口完整。
- 示例文件能表达目标数据形态。
- 第一阶段没有越界实现完整功能。
- 后续开发者能基于仓库继续推进 Schema、校验器、导出器和 Agent 编排。
