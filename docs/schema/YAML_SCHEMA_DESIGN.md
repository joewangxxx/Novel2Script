# YAML Schema 设计说明

## 为什么 YAML 是主数据源

Novel2Script 的主数据需要同时服务作者审阅、程序校验、Agent 审校和 Fountain 导出。YAML 相比纯文本更结构化，相比 JSON 更适合人工阅读和编辑，因此适合作为剧本改编过程中的主数据源。

YAML 文件应承担以下职责：

- 保存剧本结构和内容。
- 记录原文溯源。
- 标记 AI 推断和低置信内容。
- 为校验器、审校 Agent 和导出器提供统一输入。

## 为什么设计 Scene + Beat + Element

小说到剧本的改编需要分层表达：

- Scene：可拍摄的场景单元，包含地点、时间、角色和整体戏剧目标。
- Beat：场景内部的动作和冲突推进单元。
- Element：具体可导出的剧本元素，例如动作、对白、转场、注释或镜头提示。

这种结构能让系统既保留宏观叙事，又能检查每个场景是否具备可拍摄的行动和冲突。

## Beat 字段设计

每个 Beat 至少包含以下字段：

- `objective`：角色在这一拍中想达成什么。
- `tactic`：角色用什么方式争取目标。
- `obstacle`：阻碍目标达成的力量。
- `conflict`：角色、环境或内心之间的直接冲突。
- `stakes`：失败的代价。
- `turn`：这一拍发生了什么变化。
- `externalized_action`：把小说中的心理、叙述或背景信息外化为可拍摄行动。

这些字段强迫改编结果从“讲述故事”转向“呈现场景”，也为后续审校 Agent 提供明确检查点。

## source_trace 为什么要细化到章节和段落

改编过程中最常见的问题是 AI 添加无根据设定、删改关键因果或误读人物动机。`source_trace` 至少应指向章节和段落范围，让作者能快速判断某个场景、Beat 或元素来自哪里。

建议结构：

```yaml
source_trace:
  chapter: 1
  paragraph_range: [3, 5]
  note: "角色第一次发现异常声响。"
```

## ai_tags 为什么必须标记低置信区域

AI 生成内容天然包含推断。系统不能把推断伪装成原文事实。`ai_tags` 用于标记：

- 是否由 AI 推断。
- 是否低置信。
- 是否需要人工确认。
- 是否存在改编风险。

审校工具可以优先处理这些区域，作者也能清楚区分原文信息和改编补足。

## 为什么 Fountain 不能作为主数据源

Fountain 适合导出剧本格式，但不适合作为主数据源。它难以稳定承载以下信息：

- 章节和段落级溯源。
- Beat 的目标、策略、阻碍、冲突和转折。
- AI 置信度标记。
- 多 Agent 审校记录。
- 可机器校验的嵌套结构。

因此，推荐流程是 YAML 作为主数据源，Fountain 作为导出产物。
