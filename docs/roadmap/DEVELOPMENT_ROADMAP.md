# 开发路线图

## 阶段 1：Schema 与样例优先

建立仓库结构、文档体系、Schema 骨架和样例文件。目标是让团队先统一数据形态和边界，不提前绑定具体模型或前端方案。

## 阶段 2：确定性校验器与导出器

实现 JSON Schema 校验、source_trace 覆盖率检查、Beat 完整性检查和 Fountain 导出器。该阶段应优先可测试、可复现的确定性逻辑。

## 阶段 3：小说解析

实现章节、段落、角色、地点、事件和时间线的解析流程。可以先使用规则和人工标注样例，再逐步接入模型能力。

## 阶段 4：大纲与角色圣经

生成改编大纲、人物目标、关系、语言风格和角色弧线。该阶段要保留原文依据，避免无根据扩写。

## 阶段 5：结构化剧本生成

根据改编大纲和角色圣经生成 Scene + Beat + Element YAML 初稿。所有关键新增内容都必须标记 `ai_tags`。

## 阶段 6：多 Agent 审校

接入角色一致性、节奏、对白自然度、可拍摄性等审校 Agent。审校 Agent 只输出 patch 建议，不直接覆盖用户稿件。

## 阶段 7：Fountain 有限回写

支持从 YAML 导出 Fountain，并探索有限范围内从 Fountain 修改回写到 YAML。回写必须受约束，避免破坏主数据结构。

## 阶段 8：可视化工作台

构建面向作者的可视化工作台，展示原文、结构化剧本、溯源、审校建议和变更历史。该阶段再考虑前端框架、状态管理和协作体验。
